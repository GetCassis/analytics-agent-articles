# Contributing

We’re looking for firsthand accounts of building and running analytics agents. Explain what the team built, why it chose that approach, or what went wrong. Code, architecture diagrams, and worked examples help.

Open an issue or pull request with the original link, publication date, and a sentence about why someone should read it. If you wrote it or work on the product, just say so.

For a pull request:

1. Add a short entry to the README. Internal builds are alphabetical by company. Keep multiple articles about the same system together.
2. Add the original title, author names, date, supported stack tags, and a short description to reading-notes.md under the company heading.
3. Use `Internal deployment` for a team’s own use and `Vendor implementation` for products built for customers. Leave technical studies unlabelled when neither fits.
4. Mention required subscriptions or if the source is a video. Only add code links when the article actually provides code readers can use.

A product announcement, general prediction, or framework tutorial usually won’t give readers enough about an actual implementation. Related technical articles can go in Related reading when they add something the internal accounts don’t cover.

Please check the original article before suggesting stack tags. A coding tool used to build an agent isn’t necessarily the tool running it.

Include co-authors credited by the article. Add GitHub handles when an author’s own links or a matching public profile establish the connection; a similar name alone is not enough. If no individual author is credited, use the publisher.
